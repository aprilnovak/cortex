## DAGMC Model

- Initial CAD model created by **BlueMira** code.
- Plasma information generated by **PROCESS** (via BlueMira).
- CAD model improved in **Fusion 360**.
- DAGMC model generated in **Coreform Cubit**.

Three breeder blanket concepts are supported, each with its own DAGMC file:

| Breeder Type | Description                        | DAGMC File              |
|--------------|------------------------------------|-------------------------|
| `WCLL`       | Water-Cooled Lithium Lead          | `eudemo_wcll.h5m`       |
| `HCLL`       | Helium-Cooled Lithium Lead         | `eudemo_hcll.h5m`       |
| `HCPB`       | Helium-Cooled Pebble Bed           | `eudemo_hcpb.h5m`       |

Note: `fast_slab` DAGMC currently only exists for `WCLL` model (see `_FAST_SLAB_DAGMC_FILENAMES`
in `inputs.py`).

## Requirements

### Python packages

```bash
pip install pydagmc numpy pandas matplotlib h5py
```

Also required:

```bash
python -m pip install tokamak-neutron-source==0.1.4
```

Note: The model was validated using the previous version of tokamak-neutron-source.
(The newer version changed the overall results and we will communicate with the developers)

### Environment variable

The depletion chain file path must be set **before running any script** — not
just depletion. If `OPENMC_CHAIN_FILE` is unset the code will exit immediately
with an error.

```bash
export OPENMC_CHAIN_FILE=/path/to/chain.xml
```

Add this line to `~/.bashrc` to make it permanent.

The same must be done for the cross-sections (`OPENMC_CROSS_SECTIONS`).

Our models have been run with cross-section data from `ENDF/B-VIII.0` provided in `https://openmc.org/data/`.
The same link provides the Depletion Chain file (`ENDF/B-VIII.0-sfr`).

## Configuration

All user settings live in `inputs.py`. This is the **primary file to edit**
between runs.

### Simulation type

```python
SIM_TYPE     = "tokamak"   # "tokamak" | "slab" | "fast_slab"
BREEDER_TYPE = "WCLL"      # "WCLL"    | "HCLL" | "HCPB"
ENVIRONMENT  = "TESTING"   # "CORTEX"  | "TESTING"
```

| `ENVIRONMENT` | Behaviour |
|---------------|-----------|
| `TESTING`     | Slab static files loaded directly from the tokamak results folder |
| `CORTEX`      | Slab static files loaded from the slab folder; copied automatically from tokamak on first run |

### Materials

Materials common to all breeder types are set near the top of the materials
section. To change structural material, update this line:

```python
structural_material = materials.eurofer97(7.87)   # default
#structural_material = materials.inconel718(8.19) # alternative
```

Breeder-specific materials (coolant, breeder, multiplier) are set automatically
based on `BREEDER_TYPE`, but can be overridden in `inputs.py`.

The volume fraction of structural, coolant, breeder, and multiplier are fixed
per layer for each `BREEDER_TYPE`.

### OpenMC run settings

| Parameter                    | Default   | Description                                 |
|------------------------------|-----------|---------------------------------------------|
| `PARTICLES_PER_BATCH`        | `100_000` | Particles per batch                         |
| `USE_TRIGGER`                | `True`    | Convergence trigger;`False` = fixed batches |
| `FIXED_BATCHES`              | `10`      | Batches used when `USE_TRIGGER = False`     |
| `BATCHES`                    | `10`      | Initial batches when trigger is active      |
| `TRIGGER_MAX_BATCHES`        | `2000`    | Maximum batches with trigger                |
| `TALLY_CONVERGENCE_THRESHOLD`| `0.1`     | Relative error threshold (10%)              |
| `DO_PHOTON_TRANSPORT`        | `True`    | Include coupled photon transport            |
| `DO_WRITE_SURFACE_SOURCE`    | `False`   | Write surface source for slab runs          |

> **Note:** `DO_WRITE_SURFACE_SOURCE` must be set to `True` when running the
> tokamak simulation if you intend to generate a new surface_source.h5 file for the slab simulation.
> The surface source file it produces is a required input for all slab runs.

### Reactor parameters

| Parameter             | Default  | Description                          |
|-----------------------|----------|--------------------------------------|
| `TOTAL_FUSION_POWER_W`| `2.0e9`  | Total fusion power (W)               |
| `EV_PER_FUSION`       | `17.6e6` | Energy per fusion event (eV)         |
| `NUMBER_OF_SECTORS`   | `16`     | Tokamak symmetry sectors             |

### Depletion settings

| Parameter              | Default | Description                              |
|------------------------|---------|------------------------------------------|
| `IRRADIATION_YEARS`    | `5.0`   | Total irradiation time (years)           |
| `CONSTANT_POWER_RATIO` | `0.3`   | Fraction of full neutron source rate     |
| `REDUCED_CHAIN_LEVEL`  | `5`     | Depth of reduced depletion chain         |
| `OPENMP_THREADS`       | `None`  | Transport threads (`None` = all available) |
| `DEPLETION_PROCESSES`  | `None`  | Depletion processes (`None` = all available) |

### Reference run comparison

```python
REFERENCE_LABEL = None   # None = disabled (recommended for first-time runs)
```

> **Warning:** The default value of `REFERENCE_LABEL` in `inputs.py` is set to
> `"W_armor_eurofer_structural"`, which enables overlay plots against a saved
> reference. If no reference has been saved yet, `neutronics_post.py` and
> `depletion_post.py` will print a warning and skip the overlay — they will not
> crash. However, set `REFERENCE_LABEL = None` on first-time runs to avoid
> confusion. See [Reference Runs](#reference-runs) for how to save a reference.

## Run Order

All commands must be run from the `full_model_bluemira/` directory.

In Cortex, **tokamak and slab are independent workflows** — neither requires the
other to have been run first. The static input files that the slab needs
(`surface_source.h5` and `armor_current_neutron.json`) are pre-supplied by
Cortex and placed in the correct location beforehand. A tokamak run is only
needed if you want tokamak-specific results (full-geometry flux profiles, poloidal sweeps, albedo).

Each workflow follows the same three-phase structure:

```
1. neutronics_model.py                   →  builds and (for slab) runs the OpenMC model
2. openmc ./`SIM_TYPE`/`BREEDER_TYPE`/   →  transport run (must be run in the correct `model_xml` folder)
3. neutronics_post.py                    →  post-process neutronics results
4. depletion_model.py                    →  R2S activation depletion (and optionally D1S)
5. depletion_post.py                     →  post-process activity and decay heat
```

Note: future plans involve merging the whole simulation workflow to one file to reduce 
information tracking and avoid re-initializing openmc (and the model) more than once.

---
Both `tokamak` and `slab` models are ran with the same commands.
However, each model may have slightly different options and requirements. 
Therefore we will present each run separately.

### Tokamak neutronics + depletion

**Set in `inputs.py`:**
```python
SIM_TYPE                = "tokamak"
BREEDER_TYPE            = "WCLL"      # or HCLL / HCPB
ENVIRONMENT             = "CORTEX"
DO_WRITE_SURFACE_SOURCE = False       
```

**Step 1 — Build the model:**
```bash
python neutronics_model.py
```

Writes:
- `tokamak/WCLL/neutronics_run/model.xml`
- `tokamak/WCLL/neutronics_results/structural_maps.json`
- `tokamak/WCLL/neutronics_results/run_meta.json`

**Step 2 — Run OpenMC** (transport must be launched manually):
```bash
cd tokamak/WCLL/neutronics_run/ # or any `SIM_TYPE`/`BREEDER_TYPE`/
openmc -s 8          # -s <N> sets the number of threads; omit for all available
cd ../../../
```

Produces:
- `neutronics_run/statepoint.*.h5`
- `neutronics_run/summary.h5`
- `neutronics_run/surface_source.h5`  ← only if `DO_WRITE_SURFACE_SOURCE = True`

**Step 3 — Post-process neutronics:**
```bash
python neutronics_post.py
```

**Step 4 — Run depletion** (optional):
```bash
python depletion_model.py
python depletion_post.py
```

#### Optional: processing additional breeder chunks

By default only the equatorial outboard chunk `OB_1_b6` is post-processed.
Additional chunks can be added in `inputs.py`:

```python
NEUTRONICS_KEYS_TO_PROCESS = [
    "OB_1_b6",   # required — do not remove
    "IB_1_b4",   # example additional chunk
]
```

Valid chunk keys are derived from the geometry defined in
`EUDEMO_<BREEDER_TYPE>_inputs.json`. Only `OB_1_b6` is supported in slab
geometry.

### Slab neutronics + depletion

In Cortex, the slab can be run directly — no prior tokamak run is needed.
Cortex pre-supplies `surface_source.h5` and `armor_current_neutron.json` for
each breeder type, and `ENVIRONMENT = "CORTEX"` tells the code to read them
from the slab folder rather than from a local tokamak output.

**Required files** (pre-supplied by Cortex, placed in `slab/WCLL/`):
- `surface_source.h5`
- `armor_current_neutron.json`

**Set in `inputs.py`:**
```python
SIM_TYPE                = "slab"        # or "fast_slab"
BREEDER_TYPE            = "WCLL"        # or HCLL / HCPB
ENVIRONMENT             = "CORTEX"
DO_WRITE_SURFACE_SOURCE = False
```

**Step 1 — Build and run the model:**
```bash
python neutronics_model.py
```

**Step 2 — Run OpenMC** (transport must be launched manually):
```bash
cd slab/WCLL/neutronics_run/ # or any `SIM_TYPE`/`BREEDER_TYPE`/
openmc -s 8          # -s <N> sets the number of threads; omit for all available
cd ../../../
```

**Step 3 — Post-process neutronics:**
```bash
python neutronics_post.py
```

> **Note:** Only `OB_1_b6` is supported for slab geometry. Any additional keys
> in `NEUTRONICS_KEYS_TO_PROCESS` are silently ignored. Poloidal layer sweeps
> and albedo calculations are automatically disabled for slab runs.

**Step 4 — Run depletion** :
```bash
python depletion_model.py
python depletion_post.py
```

---

### Depletion settings

Depletion imports `neutronics_model.py` internally, so `inputs.py` must be
configured with the correct `SIM_TYPE` and `BREEDER_TYPE` before running.

The D1S / depletion feature toggles live at the top of `depletion_model.py` itself —
this is the one exception to the "only edit `inputs.py`" rule:

```python
RUN_D1S       = True    # D1S shutdown dose rate calculation
RUN_DEPLETION = True    # Openmc activation and depletion
```

As a stardard simulation, these toggles must be always True.

Parallelism is controlled in `inputs.py`:

```python
OPENMP_THREADS      = None   # neutron transport threads (None = all available)
DEPLETION_PROCESSES = None   # depletion solver processes (None = all available)
```

## Output Structure

Results are written under `<SIM_TYPE>/<BREEDER_TYPE>/`. The slab layout mirrors
the tokamak layout except that it contains no poloidal plots (such as `layer_Armor_region1_only/` folder)
and the albedo sub-folder is absent.

```
tokamak/WCLL/
├── neutronics_run/
│   ├── model.xml
│   ├── statepoint.*.h5
│   └── surface_source.h5          # only if DO_WRITE_SURFACE_SOURCE = True
├── neutronics_results/
│   ├── structural_maps.json
│   ├── run_meta.json
│   ├── cell_material_volume_map.json
│   ├── OB_1_b6/                   # one folder per key in NEUTRONICS_KEYS_TO_PROCESS
│   │   ├── profiles/              # profile_<quantity>_OB_1_b6.csv  (flux, heating, DPA, H, He)
│   │   ├── plots/                 # *.png figures for profiles/*.csv (+ *_vs_ref.png if reference enabled)
│   │   ├── spectra/               # spectrum CSVs and figures
│   │   ├── albedo/                # tokamak only
│   │   │   └── armor_current_neutron.json    # used as slab static input
│   │   ├── nuclide_breakdown/     # per-cell nuclide CSV breakdowns
│   │   └── summary_results.csv
│   └── layer_<tag>_region1_only/  # tokamak only; one folder per entry in POLOIDAL_LAYERS
│       ├── profiles/              # profile_<quantity>_<tag>.csv  (x-axis = poloidal index)
│       └── plots/                 # *.png poloidal figures (+ *_vs_ref.png if reference enabled)
├── depletion_run/
│   ├── r2s/
│   │   └── activation/
│   │       ├── depletion_results.h5
│   │       └── cell_material_map.csv
│   └── d1s/                       # written only when RUN_D1S = True
│       └── sdr/
│           ├── sdr_time_plasma.png
│           ├── sdr_timeseries_plasma_vvpf.csv
│           ├── sdr_summary_OB_1_b6.csv
│           └── csv/               # per-timestep SDR profiles
└── depletion_results/
    └── OB_1_b6/
        ├── activity/              # activity_all_cells.csv, per-cell figures
        └── decay_heat/            # decayheat_all_cells.csv, per-cell figures
```

## Reference Runs

A reference (gold) run saves the current post-processing results so that future
runs can overlay comparison plots automatically.

### Saving a reference

Edit the label and material description at the top of `save_reference.py`:

```python
LABEL      = "W_armor_eurofer_structural"
ARMOR      = "W"
STRUCTURAL = "eurofer97"

# Optional: override sim_type / breeder_type instead of reading from inputs.py
SIM_TYPE_OVERRIDE     = None   # e.g. "tokamak" | "slab" | "fast_slab"
BREEDER_TYPE_OVERRIDE = None   # e.g. "WCLL"    | "HCLL" | "HCPB"
```

Then run:

```bash
python save_reference.py
```

Re-run (after changing `inputs.py`, or using the override variables) for each
`SIM_TYPE` / `BREEDER_TYPE` combination you want to include under the same label.

### Enabling comparison overlays

In `inputs.py`, set:

```python
REFERENCE_LABEL = "W_armor_eurofer_structural"  # None to disable
```

When enabled, every profile plot will generate an additional `_vs_ref.png`
figure with the reference overlaid as a dashed black line.

### Listing saved references

```bash
python reference_manager.py
```

## Known Limitations

- **Slab geometry only supports `OB_1_b6`.** The slab DAGMC file is built
  around the equatorial outboard chunk. IB or other OB chunks are not
  supported without regenerating the slab DAGMC geometry.

- **`fast_slab` is DAGMC file exists for WCLL only.** DAGMC files
  need to be generated for the remaining breeder types.

- **`_get_breeder_reflective_cuts` is fragile.** The automatic reflective cut
  detection can fail if a different breeder chunk is targeted.

- **Depletion imports `neutronics_model.py`.** The full neutronics model is
  rebuilt and re-synced every time `depletion_model.py` is run. This will be
  resolved in a future refactor that merges the scripts.
